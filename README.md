# Fabric Medic

Windows 上的 Minecraft 模组体检工具。选中一个实例的 `mods` 文件夹，它会读取每个 jar 里的元数据，判断版本区间、模组冲突和缺失前置，给出可预览的修复方案，动手之前先备份。

支持 **Fabric**、**Forge**，以及 **Forge + Connector（Mix 模式）**。

---

## 它解决什么问题

整合包装完打不开，十次里有八次是这三件事：

- 某个模组要求的游戏版本和当前实例对不上
- 两个模组声明了冲突，或者同 ID 装了两份
- 少了一个前置，游戏直接崩在加载阶段

这些信息全都写在 jar 的 `fabric.mod.json` / `mods.toml` 里，只是没人愿意一个个翻。Fabric Medic 把它们读出来，摆到一张表上。

## 下载与运行

到 [Releases](../../releases) 下载最新的 `FabricMedic-v2.2.zip`，解压，双击 `FabricMedic-v2.2.exe`。

- 免安装，不写注册表，不放后台服务
- 配置存在 `%LOCALAPPDATA%\FabricMedic\workbench.json`
- 出问题会写 `%LOCALAPPDATA%\FabricMedic\crash.log`

**只有从源码跑才需要环境**：Python 3.12、Tk、Pillow。

```
pip install pillow
python main.py
```

## 使用方法

### 1. 选实例

主页点击 **查找我的游戏版本**，从左侧选择一个版本即可扫描。找不到时点击 **手动添加版本**，选择版本目录或 `mods` 文件夹。

工具会自己从同级的实例 json 里读游戏版本；读不到会弹框让你手填。

选过的实例会留在左侧「版本」里，下次点一下就能切回来。

### 2. 扫描

选完目录会自动扫一遍。顶上一行显示当前路径、游戏版本和加载器。

如果加载器不对，点左上角 **Fabric Medic 旁边的箭头**，在下拉里切 Fabric / Forge，它会按对应规则重新扫。

### 3. 看结果

表格三列：**处理状态 / 模组文件 / 版本要求或冲突对象**。

| 状态 | 含义 |
|---|---|
| ✓ 保留 | 没问题，保持启用 |
| ⚠ 缺前置 | 它依赖的某个模组不在列表里，第三列写着缺什么 |
| ⚠ 待替换 | 依赖版本不符，有可替换的候选 |
| ＋ 待安装 | 修复时找好的文件，还没落盘 |
| ↻ 备份替换 | 用新版本换掉旧版本，旧的进备份 |
| × 移出 | 会被移出 `mods`（进备份，不删除） |

**点任意一行**可以在「保留」和「移出」之间切换，自己决定留谁。有冲突对的话，第三列会写出冲突对象。

### 4. 修复依赖

版本页点击 **生成修复方案**，它会去 Modrinth 找匹配当前游戏版本和加载器的文件；确认列表后点击 **确认应用方案**。

查找过程实时显示在右侧「输出」面板里，最后一行是结果。找到的文件先以「＋ 待安装」出现，**不会直接写入**。

想一步到位就用 **自动安装并校验**：找文件、下载、校验哈希、落盘，全程不用手动点，装完自动重扫。

### 5. 应用方案

点 **操作面板 → 应用方案**，把当前方案落盘：要移出的进备份，要装的写进 `mods`。

应用前请先关掉游戏。

### 6. 反悔

点 **操作面板 → 恢复备份**，按批次还原到应用之前的状态。

备份位置：

```
<实例目录>\FabricMedic\.Backup\<时间戳>\
```

时间戳形如 `20261105-072301`，每次应用生成一个批次，互不覆盖。

## 支持范围

**做**：读元数据、判版本区间（`>=` `<` `~` `*` 等常见写法）、查同 ID 重复、查声明冲突、查缺失前置、从 Modrinth 取文件、校验后落盘、备份与还原。

**不做**：

- 不启动游戏，不碰启动器
- 不改模组内容，只增删文件
- 依赖只从 Modrinth 找，CurseForge 不支持
- 客户端模组为主；服务端专用模组可能没有客户端元数据，会被标成"未识别文件"

---

## 常见问题

**扫出来一堆"保留未识别文件"**
加载器选错了，或者这些 jar 确实没有元数据（比如资源包放错了地方）。先切加载器再扫。

**修复依赖找不到文件**
多半是版本区间真的对不上。比如某个模组要求 `sodium 0.9.x`，而当前游戏版本下 Modrinth 上只有 `0.8.9`，那就无解，只能换模组版本。输出面板会写明是哪个依赖、要什么版本。

**修复依赖卡住**
查找有 2 分钟超时，超时会明确提示并释放界面。如果一直失败，检查网络能否访问 `api.modrinth.com`。

**应用之后游戏打不开**
操作面板 → 恢复备份，选最近那个批次。

**窗口不见了**
点左上角箭头旁边没有隐藏功能，直接看任务栏。快捷键功能未实现。

## 从源码构建

```
python -m PyInstaller --onefile --windowed --name FabricMedic-v2.2 main.py --noconfirm --distpath dist --workpath build
```

需要先 `pip install pyinstaller`。产物在 `dist\`。

## 目录结构

```
main.py        主界面与流程
core.py        元数据解析、版本区间判定、Modrinth 查询、落盘与备份
forge.py       mods.toml 的版本区间解析
workbench.py   界面框架（主题、动效、实例列表）
chrome.py      自绘标题栏与圆角控件
motion.py      页面与内容切换动效
```

- 重复依赖按目标与原因分组，默认显示摘要，详情可展开和导出。
- 查找显示阶段和耗时，支持取消、120 秒任务预算与 8 秒网络读取超时。取消需等待当前阻塞调用返回。

## v2.2

版本列表右键「从列表移除」仅删除记录，不删除游戏文件。设置中的「清理缓存」清理下载缓存，不影响配置、游戏和备份。再次自动发现时，被移除的版本仍可能重新出现在列表。
